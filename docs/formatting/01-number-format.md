# 数字格式：常规、货币、日期、百分比与自定义格式代码

- **所属栏目**：C02 单元格与表格格式 ／ C02-L2-1 数字格式
- **适用版本**：Excel 2016／2019／2021／365
- **难度**：入门
- **预计阅读时长**：20 分钟
- **更新日期**：2026-11-09

## 1. 学习目标

学完本篇，你将能够：
- 区分"单元格的值"与"单元格的显示格式"，知道改格式不改值
- 正确设置货币、百分比、日期三种最常用数字格式
- 写出常用的自定义格式代码（如 0.00、#,##0、yyyy-mm-dd、[红色]负数）
- 诊断并修复"数字变日期"、"百分比放大 100 倍"、"前导 0 丢失"三类格式事故

## 2. 基础概念

**值与格式分离**：单元格里存的是值（如 0.25），显示的是格式（如 25%）。改格式只改变观感，不改变参与计算的值——`0.25` 显示成 25% 后，求和结果不变。这是理解数字格式的第一性原理，也是"百分比放大 100 倍"事故的根源：先输入 25 再设百分比格式，Excel 会把 25 理解成 2500%。

**常规格式**：默认格式，数字按原样显示，超过 11 位的大数字自动变科学计数法。身份证号、银行卡号变科学计数法，就是常规格式在作怪——解法是先设文本格式再输入。

**货币与会计专用**：货币格式给数字加 ¥ 符号与千分位（如 ¥1,234.56）；会计专用格式把 ¥ 符号左对齐、小数点对齐，适合财务报表。两者都不改变数值本身。

**日期格式**：Excel 的日期本质是序列值（1900-01-01 是 1，2026-11-09 是 45961），显示格式决定它看起来是"2026/11/9"还是"2026 年 11 月 9 日"。日期能直接加减（`2026-11-09 减 2026-11-02 = 7`），靠的就是序列值。

**自定义格式代码**：格式代码分四段"正数;负数;零值;文本"，如 `#,##0.00;[红色]-#,##0.00;"-"` 表示正数带千分位两位小数、负数红色带减号、零显示一个短横。常用占位符：`0` 强制占位显示 0，`#` 有数才显示，`?` 按空格占位对齐小数点。

## 3. 操作步骤

1. 设货币：选中金额列，开始→数字格式下拉选"货币"，或按 `Ctrl + Shift + 4`（货币快捷键）；会计专用在同一菜单里选"会计专用"。
2. 设百分比：先确认值是小数形式（0.25 不是 25），再按 `Ctrl + Shift + 5` 或点 `%` 按钮；需要两位小数时点"增加小数位数"。
3. 设日期：选中日期列，开始→数字格式下拉选"短日期"或"长日期"；需要"2026-11-09"这种形式时用设置单元格格式→自定义→输入 `yyyy-mm-dd`。
4. 自定义格式：选中区域按 `Ctrl + 1`→数字→自定义，在类型框输入格式代码，如 `0.00"元"`（数字后加"元"字后缀显示）。
5. 批量清格式：选中区域，开始→清除→清除格式，回到常规格式；只清格式不删值。
6. 检查真值：点任一单元格看编辑栏——编辑栏显示的是真实值，单元格显示的是格式效果；两者不一致时以编辑栏为准。

## 4. 图文示例

一张报销表：A 列日期（2026-11-02），B 列金额 1234.5，C 列占比 0.25。把 A 列设为 `yyyy-mm-dd` 显示"2026-11-02"；B 列设货币格式显示"¥1,234.50"；C 列设百分比显示"25%"。D 列自定义格式 `0.00"元"`，输入 80 显示"80.00元"，值仍是 80，可正常求和。核对：选中 C2 看编辑栏仍是 0.25，证明格式没改值。

## 5. 公式和代码

```excel
=B2*0.13 → 160.49（B2=1234.5 时）
=A3-A2 → 7（A2=2026-11-02，A3=2026-11-09 时）
=TEXT(0.25,"0%") → 25%
```

- `=B2*0.13` → 160.49：1234.5×0.13=160.485，四舍五入到分是 160.49；货币格式显示 ¥160.49，值不变
- `=A3-A2` → 7：日期相减得天数：11 月 9 日减 11 月 2 日是 7 天（序列值相减）
- `=TEXT(0.25,"0%")` → 25%：TEXT 函数把值按格式代码转成文本"25%"，结果是文本，不再参与数值计算

## 6. 实际工作场景

### 财务做报销汇总表

金额列统一货币格式两位小数，合计行加粗；占比列用百分比格式一位小数。发给领导前检查：合计值用 SUM 重算一遍，确认格式没有掩盖真实值（编辑栏核对）。

### 人事做工号表

工号"00123"前导 0 会丢失：先把列设为文本格式再录入，或自定义格式 `00000`（5 位不足补 0）。已录丢的 0 无法找回，只能重新录入。

## 7. 常见错误

| 错误现象 | 原因 | 解决方案 |
|---|---|---|
| 百分比显示 2500% | 先输 25 再设百分比格式 | 先设格式再输 0.25，或输入后除以 100；已错的批量用选择性粘贴→除 100 修正 |
| 身份证号变科学计数法 | 常规格式下长数字被当数值 | 先设文本格式再输入；已变的无法恢复原值，需重新录入 |
| 日期输入后变 45961 | 单元格是常规格式，序列值露出来了 | 选中区域设为短日期格式 |
| 前导 0 丢失（00123 变 123） | 数值格式不保留前导 0 | 先设文本格式，或自定义格式 00000 |
| 自定义格式代码不生效 | 代码写错段或用了中文标点 | 分号用英文 ;，引号用英文双引号，代码分段不超过四段 |
