# 查询管理与刷新：让月报自己更新

- **所属栏目**：C09 Power Query ／ C09-L2-5 查询管理与刷新
- **适用版本**：Excel 2016／2019／2021／365（内置，位于“数据”选项卡）
- **难度**：中级
- **预计阅读时长**：25 分钟
- **更新日期**：2026-11-10

## 1. 学习目标

学完本篇，你将能够：
- 管理查询（改名、复制、引用、分组、设置加载方式），并说出引用与复制的区别
- 设置刷新（手动刷新、全部刷新、打开文件自动刷新），并说出刷新顺序的规则
- 处理刷新报错与步骤顺序问题，不用删除错误掩盖问题

## 2. 基础概念

### 2.1 查询属性：改名要趁早

右键查询→“属性”，可以改名、写说明、看查询的加载设置。改名要趁早：查询名默认是“查询1”这种无意义的名字，M 代码里引用查询用的是 `#"查询名"`，改名后引用处自动跟着改。建议命名：来源加内容，如“销售明细-2026”、“订单-带客户名称”，不要用“查询1”。

### 2.2 刷新设置

| 设置位置 | 作用 |
|---|---|
| 右键查询→“刷新” | 只刷新这一个查询 |
| “数据→全部刷新” | 刷新工作簿里全部查询与透视表 |
| 查询属性→“打开文件时刷新数据” | 每次打开文件自动刷新，适合固定月报 |
| “数据→查询与连接→右键→属性→使用情况” | 设后台刷新、刷新间隔（分钟） |

要点：源文件变了，Excel 不会自动重算，必须手动刷新；“全部刷新”的顺序按查询依赖关系自动排，先刷新被引用的查询，再刷新引用它的查询。

### 2.3 引用与复制的区别

- 分组：查询多了（十几个）可以在“查询与连接”窗格里建组，如“源数据”“中间表”“输出表”，按流水线分。
- 引用与复制的区别：右键→“引用”是新建一个查询，起点是原查询的结果（改原查询会连带影响）；“复制”是复制一份 M 代码（改原查询不影响副本）。要基于清洗结果再做分支，用引用；要留一个备份版本，用复制。
- 加载方式：中间查询设为“仅创建连接”，不加载到工作表，文件更小、刷新更快；只有最终输出表才加载到工作表。

### 2.4 错误处理：保留错误，不要删除错误

查询出错时，单元格显示错误值，编辑器里出错的行整行标红。常见处理：

- 点出错的单元格看错误信息（如“Expression.Error: 找不到列”），按信息定位到具体步骤。
- “转换→替换错误”可以把某列的错误值统一换成空或 0，适合脏数据。
- “主页→保留错误”只留出错的行，单独成一张错误清单，逐行修源数据。
- 不要用“删除错误”掩盖问题：删掉的错误行不会再出现，月报总数就悄悄少了。

## 3. 操作步骤

1. 改名：右键查询→“属性”，改成“来源+内容”的名字，如“销售明细-2026”。
2. 分组：查询多了在“查询与连接”窗格建组：源数据、中间表、输出表。
3. 设加载方式：中间查询右键→“加载到”→“仅创建连接”；最终输出表才加载到工作表。
4. 手动刷新：右键查询→“刷新”；或“数据→全部刷新”。
5. 自动刷新：查询属性→勾选“打开文件时刷新数据”。
6. 查错：出错时点出错的单元格看错误信息，按信息定位到具体步骤。
7. 修步骤：点报错的步骤，看公式栏里引用的列名，逐个改成新列名；或删掉报错步骤重做。

## 4. 图文示例

### 4.1 刷新：源文件更新后同步

源文件更新后，Power Query 的结果同步办法：右键查询→“刷新”，或“数据→全部刷新”；查询步骤存在工作簿里，刷新即按步骤重跑一遍。打开文件自动刷新在查询属性里勾选“打开文件时刷新数据”。

示例：配套 3 个 csv（1 月 14690、2 月 9730、3 月 18270）追加后 12 行、总计 42690。往文件夹里再丢一个 4 月文件（4 行），右键刷新，查询变成 16 行；总计随之变化，不用重新清洗。

### 4.2 保留错误：10 行里 2 行出错

10 行销售明细里 2 行金额列是错误值（源文件里写了“N/A”）。“主页→保留错误”只留这 2 行，单独成一张错误清单，逐行修源数据；修好后刷新，错误清单变空。不要用“删除错误”：删掉的 2 行不会再出现，月报总数就悄悄少了 2 行的金额。

### 4.3 引用与复制：分支与备份

清洗好的“销售明细”查询，要基于它再做两个分支：一张按销售员汇总、一张按月份汇总。两个分支都用“引用”新建查询，起点都是清洗结果；改清洗逻辑，两个分支一起变。另留一个备份版本用“复制”，改原查询不影响副本。

## 5. 公式和代码

### 5.1 刷新后核对：金额合计

查询加载回工作表后，用公式核对数字是否与配套文件一致：

```excel
=SUM(表1[金额]) → 42690
```

“表1”是刷新后加载的销售明细表结构化引用，合计应为 42690；刷新后合计变了，先看行数，再看是不是新文件并进来了。

### 5.2 替换错误的 M 写法（未执行验证）

```m
// 把“金额”列的错误值统一换成 0（界面：转换 → 替换错误）
替换错误 = Table.ReplaceErrorValues(上一步, {{"金额", 0}})
```

读法：`Table.ReplaceErrorValues(表, {{列名, 替换值}})`，把“金额”列的错误值换成 0。注意：替换错误会掩盖脏数据，适合已知原因的脏数据；原因不明的错误先用“保留错误”单独成清单修源数据。本段代码未在 Power Query 内执行验证（无 Power Query 运行时），函数名与参数签名对照 Microsoft Learn 的 M 函数参考核对过。

## 6. 实际工作场景

### 6.1 月度销售报表自动化实战：刷新这一步

场景接 01-获取数据篇：财务每月从系统导出“销售2026-XX.csv”，要出“销售员×月份”的汇总报表。配套文件用 3 个月模拟 12 个月（真实场景下文件夹里放 12 个文件，做法完全相同）。

1. 每月系统导出“销售2026-10.csv”，丢进“D:\月报\”文件夹。
2. “从文件夹”获取并合并（做法见 01 篇 4.1.2 节），得到原始表（3 个月模拟：12 行，总计 42690）。
3. 清洗：提升标题→改类型（日期/数字）→填充部门→拆分“省-市”→删除空行（见 02-转换操作篇）。
4. 合并查询客户档案带出客户名称（左外部，O004 这类无档案订单会留空，见 03-合并与追加篇）。
5. 逆透视 12 个月份列（如果是交叉表，见 02-转换操作篇）。
6. “关闭并上载”→生成干净的表，上面做透视表出报表。
7. 下个月：新 CSV 丢进文件夹，右键刷新——全自动。

结果核对：上载后 `=SUM(表1[金额])` 应为 42690；透视表按销售员分组：王芳 14821、李明 11674、陈静 16195；按月份分组：1 月 14690、2 月 9730、3 月 18270。三个口径的总数都是 42690，任一口径对不上，先查清洗步骤是否丢了行。

### 6.2 刷新报错：三步定位

刷新弹错时按顺序查三处：源文件是不是改名或移走了、文件夹里是不是混进非数据文件、查询步骤里有没有引用被删的列。前两处是路径问题，后一处是步骤问题：点报错的步骤，看公式栏里的列名，逐个改成新列名。

## 7. 常见错误

| 错误现象 | 原因 | 解决方案 |
|---|---|---|
| 打开文件不自动刷新 | 没勾选“打开文件时刷新数据” | 查询属性里勾选；或每次手动点“数据→全部刷新” |
| 刷新时弹凭据窗口 | 数据库或网页来源需要账号密码 | 在凭据窗口输入账号密码；或“数据→查询与连接→数据源设置”里清除旧凭据重输 |
| 从文件夹合并报错（找不到文件） | 文件夹里混进了非数据文件，或示例文件被删改名 | 文件夹只放同结构数据文件；删掉混入的文件后刷新 |
| 刷新后金额求和变计数 | “金额”列是文本型 | 点列类型图标改成数字；或在查询里加一步改类型，放在筛选之前 |
| （Expression.Error: 找不到列） | 前面的步骤删了列或改了列名，后面的步骤还在引用旧列名 | 点报错步骤，看公式栏里的旧列名，逐个改成新列名；或删掉报错步骤重做 |
| 查询结果行数比源文件少 | 某步筛选或去重误删了行，或改类型把非法值变成了错误 | 逐个点“应用的步骤”，看每步行数变化，定位丢行的步骤 |
| 引用改了原查询，分支跟着变了 | “引用”是新建查询，起点是原查询的结果 | 这是正常现象：要留备份版本用“复制”，改原查询不影响副本 |
