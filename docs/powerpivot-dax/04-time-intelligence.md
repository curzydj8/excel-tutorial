## 2. 基础概念

### 2.1 为什么必须建日期表

时间智能函数（TOTALYTD、SAMEPERIODLASTYEAR、DATEADD）不是直接算订单表的日期，而是先在日期表上平移日期、再去订单表取值。如果没有日期表，会出现三个问题：

1. 没有订单的月份直接消失：订单表只有 2025-01、02、03、06 和 2026-01、02、03 有记录，2025-04、05 没有订单；按订单日期分组，4 月和 5 月根本不出现，折线图会断掉。
2. 去年同期对不上：SAMEPERIODLASTYEAR 要把 2026-03 平移到 2025-03，没有一张连续的日期表，平移没有落点。
3. 年初至今算不全：TOTALYTD 要从 1 月 1 日累计到当前日期，订单表缺失的日期会让累计口径不稳定。

日期表就是一张“日历”：从开始日期到结束日期，每日一行，有没有订单都有这一行。透视表按日期表的月分组，12 个月永远齐全，没有订单的月份显示空白而不是消失。

### 2.2 日期表的 6 条要求

按 Microsoft 官方文档，时间智能函数正常工作要求日期表满足：

1. 日期列是日期类型，不能是文本。
2. 日期值唯一，不能重复。
3. 日期列没有空值。
4. 日期连续，不能缺失任何一天（包括没有订单的日子）。
5. 覆盖完整年份：开始日期与结束日期要落在完整年份的边界上（本例 2025-01-01 至 2026-03-31 覆盖 2025 全年与 2026 年一季度，2026 年只到 3 月 31 日，做全年对比时要注意口径，见 6 节）。
6. 在 Power Pivot 里标记为日期表（选中日期表 → 设计 → 标记为日期表 → 选择日期列）。

### 2.3 四个函数的分工

| 函数 | 返回什么 | 典型用途 |
|---|---|---|
| DATESYTD | 年初至今的日期表 | 配 CALCULATE 自定义累计 |
| TOTALYTD | 年初至今的表达式值 | 直接算累计销售额 |
| SAMEPERIODLASTYEAR | 去年同期的日期表 | 配 CALCULATE 算去年同期 |
| DATEADD | 平移指定间隔后的日期表 | 上月、去年同期、上一季度都能算 |

记住一个等式：TOTALYTD 是 CALCULATE + DATESYTD 的简写，两者结果完全一样。DATEADD 是通用平移，SAMEPERIODLASTYEAR 是 DATEADD(日期, -1, YEAR) 的简写。

## 3. 操作步骤

1. 在 Power Pivot 窗口新建计算表“日期表”：点“新建表”或用 DAX 建表，公式见 5.1 节；生成后确认行数是 455 行（2025-01-01 至 2026-03-31）（待补图）。
2. 给日期表加三列计算列：年 `= YEAR(日期表[日期])`、季度 `= "Q" & FORMAT(日期表[日期], "Q")`、月 `= FORMAT(日期表[日期], "yyyy-mm")`（待补图）。
3. 建立关系：把日期表的日期拖到订单表的日期上，一对多（日期表 1 对订单表多）。
4. 标记为日期表：选中日期表 → 设计 → 标记为日期表 → 日期列选“日期” → 确定。没标记时时间智能函数可能返回空白（待补图）。
5. 在订单表新建度量值“年初至今销售额”：公式 `= TOTALYTD([总销售额], 日期表[日期])`。
6. 在订单表新建度量值“去年同期销售额”：公式 `= CALCULATE([总销售额], SAMEPERIODLASTYEAR(日期表[日期]))`。
7. 在订单表新建度量值“同比增长率”：公式 `= DIVIDE([总销售额] - [去年同期销售额], [去年同期销售额])`，格式选百分比。
8. 验证：透视表行拖日期表的月、值拖总销售额和去年同期销售额；2026-03 一行应显示 16000 与 4000，同比 300.00%（待补图）。

## 5. 公式和代码

DAX 语法经 Microsoft 官方文档核对；输入表与预期结果经 Python 独立验算；未在 Excel 内执行验证。以下示例的输入表均为配套示例文件里的表。

### 5.1 建日期表

```dax
日期表 = CALENDAR(DATE(2025, 1, 1), DATE(2026, 3, 31))
```

运行结果：生成一张只有一列（日期）的表，共 455 行，从 2025-01-01 到 2026-03-31，每日一行，无缺失。455 = 2025 年 365 天 + 2026 年 1 至 3 月 90 天（31+28+31）。

给日期表加年、季度、月三列（计算列）：

```dax
年 = YEAR(日期表[日期])
季度 = "Q" & FORMAT(日期表[日期], "Q")
月 = FORMAT(日期表[日期], "yyyy-mm")
```

运行结果：2026-03-22 一行的年是 2026、季度是 Q1、月是 2026-03；2025-06-10 一行的年是 2025、季度是 Q2、月是 2025-06。

### 5.2 TOTALYTD 与 DATESYTD：年初至今

```dax
年初至今销售额 = TOTALYTD([总销售额], 日期表[日期])
```

运行结果：筛选到 2026-03 时，年初至今销售额 = 44600（2026-01 的 21000 + 2026-02 的 7600 + 2026-03 的 16000）。筛选到 2026-02 时是 28600（21000+7600）；筛选到 2026-01 时是 21000。

等价写法（两者结果完全一样，TOTALYTD 是简写）：

```dax
年初至今销售额2 = CALCULATE([总销售额], DATESYTD(日期表[日期]))
```

运行结果：筛选到 2026-03 时同样是 44600。需要再加其他筛选条件时用 DATESYTD 写法，例如只算华东的年初至今：`CALCULATE([总销售额], DATESYTD(日期表[日期]), 客户[地区] = "华东")`，筛选到 2026-03 时是 16600（O007 15000 + O010 1600）。

### 5.3 SAMEPERIODLASTYEAR 与 DATEADD：去年同期

```dax
去年同期销售额 = CALCULATE([总销售额], SAMEPERIODLASTYEAR(日期表[日期]))
```

运行结果：筛选到 2026 年一季度（2026-01 至 2026-03）时，去年同期销售额 = 26000（2025-01 的 19000 + 2025-02 的 3000 + 2025-03 的 4000）。分月看：2026-01 对应 19000，2026-02 对应 3000，2026-03 对应 4000。

等价写法（SAMEPERIODLASTYEAR 是 DATEADD 的简写）：

```dax
去年同期销售额2 = CALCULATE([总销售额], DATEADD(日期表[日期], -1, YEAR))
```

运行结果：与上一度量值完全相同，2026 年一季度同样是 26000。

### 5.4 同比度量值

```dax
同比增长率 = DIVIDE([总销售额] - [去年同期销售额], [去年同期销售额])
```

运行结果（按月）：2026-01 同比 10.53%（(21000-19000)/19000）；2026-02 同比 153.33%（(7600-3000)/3000）；2026-03 同比 300.00%（(16000-4000)/4000）。2026 年一季度整体同比 71.54%（(44600-26000)/26000）。

注意：同比的分母是去年同期，不能拿今年累计除以去年全年。2026 年一季度 44600 除以 2025 全年 31000 得 43.87%，这个数不是同比，是“今年一季度完成了去年全年的 43.87%”，两个口径不要混用。

### 5.5 DATEADD 算环比：上月销售额

```dax
上月销售额 = CALCULATE([总销售额], DATEADD(日期表[日期], -1, MONTH))
```

运行结果：筛选到 2026-03 时，上月销售额 = 7600（2026-02 的销售额）；筛选到 2026-02 时，上月销售额 = 21000（2026-01 的销售额）。

```dax
环比增长率 = DIVIDE([总销售额] - [上月销售额], [上月销售额])
```

运行结果：2026-02 环比 -63.81%（(7600-21000)/21000）；2026-03 环比 110.53%（(16000-7600)/7600）。2026-01 的上月是 2025-12，2025-12 没有订单，上月销售额为空白，环比也是空白，这是正常的。

## 6. 实际工作场景

场景：一季度经营分析会的同比表。

- 背景：2026 年 4 月初开一季度经营分析会，老板问：今年一季度比去年一季度增长多少？哪个月增长最快？3 月环比怎么样？
- 做法：透视表行拖日期表的月，值拖总销售额、去年同期销售额、同比增长率、环比增长率四个度量值。
- 结果：三个数直接报：一季度总销售额 44600，去年同期 26000，同比增长 71.54%；增长最快是 3 月，同比 300.00%（16000 对 4000）；3 月环比 110.53%（16000 对 2 月的 7600），2 月环比是 -63.81%（7600 对 1 月的 21000），说明 2 月是淡季、3 月强势反弹。
- 容易踩的坑：不要拿 2026 年一季度的 44600 去比 2025 全年的 31000，得出的 43.87% 不是同比。同比必须是同期比同期：2026 年 1 至 3 月比 2025 年 1 至 3 月，才是 71.54%。日期表只到 2026-03-31，2026 年全年数据还没齐，全年同比现在算不了。

## 7. 常见错误

| 错误现象 | 原因 | 解决方案 |
|---|---|---|
| 时间智能度量值返回空白 | 日期表没有标记为日期表 | 设计 → 标记为日期表 → 选择日期列 |
| 去年同期返回空白 | 日期表开始太晚，去年同期没有日期落点 | 日期表至少往前多覆盖一年；2025 年的去年同期空白是正常的 |
| 没有订单的月份直接消失 | 按订单表的日期分组，而不是日期表的月分组 | 透视表行拖日期表的月，不要拖订单表的日期 |
| TOTALYTD 全年都是同一个数 | 透视表没有放日期字段，筛选上下文是全年 | TOTALYTD 按当前筛选累计；要看逐月累计，把日期表的月拖到行 |
| 同比算出来是 43.87% 之类的怪数 | 分母用了去年全年而不是去年同期 | 分母用 SAMEPERIODLASTYEAR 或 DATEADD(-1, YEAR) 的去年同期销售额 |
| DATEADD 报错“日期不连续” | 日期表缺了某些天 | 检查日期表是否用 CALENDAR 生成、起止日期是否连续 455 行 |
| 季度列显示 Q1、Q2 但排序乱了 | 季度是文本，按字母排序 | 加一列季度序号（1 至 4）做排序依据，或用年月列排序 |
| 日期列是文本型，时间智能全错 | 从 CSV 导入时日期被认成文本 | 在 Power Query 或模型里把日期列类型改为日期，再重建关系 |
