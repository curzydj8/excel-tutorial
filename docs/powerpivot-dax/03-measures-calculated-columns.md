## 1. 学习目标

学完本篇，你将能够：

- 用 RELATED 在计算列里取关联表字段，并说出它只能从多端取一端的限制

- 用 ALL 去掉筛选算出占比，算出电脑销售额占比 52.91%

本篇并入 data.json ppivot 种子 2 条：常用 DAX（总销售额 =SUM(订单[金额])；当年累计 =CALCULATE([总销售额], DATESYTD(日期表[日期]))；同比 =DIVIDE([总销售额]-[去年同期], [去年同期])）、KPI 指标（在数据模型中建度量值：销售额、利润率、完成率；度量值随切片器自动重算，一处定义处处用）。

## 2. 基础概念

### 2.1 度量值写在哪里、怎么复用

度量值统一建在事实表（本例是订单表）上，命名用中文业务名：总销售额、总利润、利润率。不要把同一个总销售额在 5 张表上各写一遍，也不要在透视表里现写一次性公式。一处定义、处处引用：客单价引用总销售额，同比引用总销售额和去年同期，改一处就全改了。

度量值之间可以互相引用，引用时只写方括号：`[总销售额]`。写度量值时先想好依赖链：基础度量值（总销售额、总利润）→ 派生度量值（利润率、客单价、同比）→ 展示度量值（完成率、排名）。

### 2.2 五个函数的分工

| 函数 | 作用一句话 | 关键点 |
|---|---|---|
| CALCULATE | 改筛选上下文后再算 | DAX 里唯一能改筛选上下文的函数 |
| SUMX | 逐行算表达式、再求和 | 迭代函数，每行都有行上下文 |
| RELATED | 取关联表（一端）的字段值 | 只能从多端取一端，写在计算列里 |
| FILTER | 按条件筛出一张子表 | 返回表，不能单独做度量值，要配聚合函数 |
| ALL | 去掉筛选（全部或指定列） | 常用来算分母（总计）和占比 |

### 2.3 KPI 的思路

KPI 不是一个公式，而是一组互相印证的度量值：规模类（总销售额 75600）、盈利类（总利润 22770、利润率 30.12%）、目标类（目标完成率 94.50%）、效率类（客单价 6300）。四个数放在一张仪表盘上，任何一个数异常都能顺着依赖链追到原因：利润率掉了，先看总利润，再看总销售额和总成本。

## 3. 操作步骤

1. 打开 Power Pivot 窗口，确认订单表已有计算列“金额”（02 篇做法），否则先补上（待补图）。
2. 在订单表新建度量值“总利润”：公式 `= SUMX(订单, 订单[数量] * (RELATED(产品[单价]) - RELATED(产品[成本])))`，格式选货币。
3. 在订单表新建度量值“利润率”：公式 `= DIVIDE([总利润], [总销售额])`，格式选百分比。
4. 在订单表新建度量值“华东销售额”：公式 `= CALCULATE([总销售额], 客户[地区] = "华东")`。
5. 在订单表新建度量值“电脑销售额占比”：公式 `= DIVIDE([电脑销售额], CALCULATE([总销售额], ALL(产品)))`，其中电脑销售额先建为 `= CALCULATE([总销售额], 产品[产品名称] = "电脑")`。
6. 在 Excel 插入数据透视表验证：行拖产品名称、值拖总销售额和电脑销售额占比；电脑一行占比应显示 52.91%，总计行占比 100%（待补图）。
7. 把 6 个度量值记到一张 KPI 清单上（名称、公式、预期结果），下次做仪表盘直接引用，不重写。

## 5. 公式和代码

DAX 语法经 Microsoft 官方文档核对；输入表与预期结果经 Python 独立验算；未在 Excel 内执行验证。以下示例的输入表均为配套示例文件里的表。

### 5.1 CALCULATE：改筛选上下文后再算

语法：`CALCULATE(表达式, 筛选条件1, 筛选条件2, ...)`。先按筛选条件改上下文，再算表达式。

```dax
华东销售额 = CALCULATE([总销售额], 客户[地区] = "华东")
```

运行结果：华东销售额 = 29600。输入是客户表地区为华东的两家客户（C001 华东公司）的订单：O001 10000 + O003 3000 + O007 15000 + O010 1600 = 29600。

```dax
电脑销售额 = CALCULATE([总销售额], 产品[产品名称] = "电脑")
```

运行结果：电脑销售额 = 40000。输入是产品为电脑的 4 笔订单：O001 10000 + O006 5000 + O007 15000 + O012 10000 = 40000。

```dax
数码类销售额 = CALCULATE([总销售额], 产品[类别] = "数码")
```

运行结果：数码类销售额 = 64000。输入是类别为数码的产品（电脑 40000 + 手机 15000 + 显示器 9000）；配件类 11600（耳机 9000 + 键盘 2600）；两者相加 75600，与总销售额一致。

注意：CALCULATE 的筛选条件会覆盖透视表里同一列的筛选。如果透视表行已经是“手机”，再用 CALCULATE 指定产品是“电脑”，结果会按电脑算，而不是手机。

### 5.2 SUMX：逐行算、再求和

语法：`SUMX(表, 表达式)`。对表里每一行算一次表达式，再把结果加起来。利润不能直接 SUM，因为利润 = 数量 ×（单价 − 成本），单价和成本在不同行不一样，必须逐行算。

```dax
总利润 = SUMX(订单, 订单[数量] * (RELATED(产品[单价]) - RELATED(产品[成本])))
```

运行结果：总利润 = 22770。逐行利润：O001 2400、O002 2700、O003 1500、O004 450、O005 1000、O006 1200、O007 3600、O008 1800、O009 3000、O010 720、O011 2000、O012 2400；12 行相加 22770。其中 2025 年利润 9250，2026 年 1 至 3 月利润 13520。

```dax
加权平均单价 = DIVIDE(SUMX(订单, 订单[数量] * RELATED(产品[单价])), SUM(订单[数量]))
```

运行结果：加权平均单价 = 1219.35。分子是总销售额 75600，分母是总数量 62（2+3+10+5+2+1+3+2+20+8+4+2）；75600 / 62 = 1219.35。不要和产品表的简单平均单价 2000 混用：2000 是 5 种产品单价的平均，1219.35 是按实际销量加权的平均。

### 5.3 RELATED：从多端取一端的字段

RELATED 只用在计算列（或迭代函数）里，从当前行所在的多端取一端表的字段。订单表是多端，产品表是一端，所以在订单表里可以 RELATED 产品表的单价和成本。

```dax
金额 = 订单[数量] * RELATED(产品[单价])
```

运行结果（计算列，每行一个值）：O001 行 10000（2 × 5000）、O002 行 9000（3 × 3000）、O003 行 3000（10 × 300）、O004 行 1000（5 × 200）、O005 行 3000（2 × 1500）、O006 行 5000（1 × 5000）、O007 行 15000（3 × 5000）、O008 行 6000（2 × 3000）、O009 行 6000（20 × 300）、O010 行 1600（8 × 200）、O011 行 6000（4 × 1500）、O012 行 10000（2 × 5000）。

反例：想在产品表里用 RELATED 取订单表的金额会报错，因为一个产品对应多笔订单，RELATED 不知道取哪一行。反方向要先用 RELATEDTABLE 取回多行，再用 SUMX 汇总（见 05 篇）。

### 5.4 FILTER：按条件筛出一张子表

语法：`FILTER(表, 条件)`。返回一张筛过的表，不能单独做度量值，必须配 SUM、COUNTROWS、SUMX 使用。

```dax
高价值订单笔数 = COUNTROWS(FILTER(订单, 订单[金额] > 8000))
```

运行结果：高价值订单笔数 = 4。输入是金额大于 8000 的订单：O001 10000、O002 9000、O007 15000、O012 10000，共 4 笔。

```dax
高价值订单金额 = SUMX(FILTER(订单, 订单[金额] > 8000), 订单[金额])
```

运行结果：高价值订单金额 = 44000（10000+9000+15000+10000）。这 4 笔占总销售额的 58.20%（44000 / 75600）。

注意：CALCULATE 里能用简单条件时优先用 CALCULATE（如 `客户[地区] = "华东"`），只有条件跨多列、或需要 OR、或需要 RELATED 跨表判断时才用 FILTER。FILTER 是逐行筛，大表上比 CALCULATE 慢。

### 5.5 ALL：去掉筛选，算分母和占比

语法：`ALL(表)` 去掉整张表的筛选，`ALL(表[列])` 只去掉某一列的筛选。算占比时分母要用 ALL 把筛选去掉，否则分子分母同时被筛，占比永远是 100%。

```dax
电脑销售额占比 = DIVIDE([电脑销售额], CALCULATE([总销售额], ALL(产品)))
```

运行结果：电脑销售额占比 = 52.91%（40000 / 75600）。如果分母不用 ALL，在产品名称为电脑的行里，分母会被筛成 40000，占比就变成 100%，是错的。

各产品占比（透视表行是产品名称，值是占比度量值）：

| 产品名称 | 销售额 | 占比 |
|---|---|---|
| 电脑 | 40000 | 52.91% |
| 手机 | 15000 | 19.84% |
| 耳机 | 9000 | 11.90% |
| 显示器 | 9000 | 11.90% |
| 键盘 | 2600 | 3.44% |
| 总计 | 75600 | 100.00% |

占比合计：52.91 + 19.84 + 11.90 + 11.90 + 3.44 = 99.99（四舍五入尾差，实际合计 100%）。

### 5.6 KPI 度量值：一套互相印证的指标

```dax
利润率 = DIVIDE([总利润], [总销售额])
```

运行结果：利润率 = 30.12%（22770 / 75600）。分年看：2025 年利润率 29.84%（9250 / 31000），2026 年 1 至 3 月利润率 30.31%（13520 / 44600）。

```dax
目标完成率 = DIVIDE([总销售额], 80000)
```

运行结果：目标完成率 = 94.50%（75600 / 80000）。全年销售目标 80000，当前完成 75600，还差 4400。2026 年 1 至 3 月单独看：目标 50000，完成 44600，完成率 89.20%。

```dax
客单价 = DIVIDE([总销售额], [订单笔数])
```

运行结果：客单价 = 6300（75600 / 12）。

KPI 清单（6 个度量值，全部建在订单表上）：

| 度量值 | 公式要点 | 预期结果 |
|---|---|---|
| 总销售额 | SUM(订单[金额]) | 75600 |
| 订单笔数 | COUNTROWS(订单) | 12 |
| 总利润 | SUMX 逐行算利润再汇总 | 22770 |
| 利润率 | DIVIDE([总利润], [总销售额]) | 30.12% |
| 客单价 | DIVIDE([总销售额], [订单笔数]) | 6300 |
| 目标完成率 | DIVIDE([总销售额], 80000) | 94.50% |

## 6. 实际工作场景

场景：销售例会的一页 KPI。

- 背景：每周一例会，老板要看上周的销售 KPI：卖了多少、赚了多少、利润率、离目标还差多少。以前每次开会前都要现算，数字还经常对不上。
- 做法：在数据模型里建好 6 个度量值（见 5.6 节清单），透视表行拖日期表的月份，值拖总销售额、总利润、利润率、目标完成率。切片器放地区和产品类别。
- 结果：以本篇数据为例，不筛条件时一行数是 75600、22770、30.12%、94.50%；点切片器选华东，四个数自动变成 29600、8220、27.77%、37.00%（29600 / 80000）。华东利润 8220 的算法：O001 2400 + O003 1500 + O007 3600 + O010 720 = 8220，利润率 8220 / 29600 = 27.77%。手工现算很容易抄错一行，度量值随切片器自动重算不会错，这就是 KPI 度量值要现算、不要手写的原因。
- 要点：KPI 度量值一处定义、处处复用；例会前只刷新数据，不重算数字。

## 7. 常见错误

| 错误现象 | 原因 | 解决方案 |
|---|---|---|
| CALCULATE 的条件不起作用 | 条件列写错了表，如把客户表的地区写成订单表的地区 | 条件里的列必须写所属表：客户[地区]，不是订单[地区] |
| SUMX 结果比 SUM 大很多 | 表达式里用了聚合函数导致重复汇总 | SUMX 的第二个参数是逐行表达式，不能再套 SUM；要汇总用 SUMX(表, 列1 * 列2) |
| RELATED 报错 | 在一端表里取多端字段，或关系没建 | RELATED 只能多端取一端；先检查关系视图里线连没连对 |
| FILTER 度量值报错“返回表” | FILTER 返回表，不能直接当度量值 | 配聚合函数：COUNTROWS(FILTER(...)) 或 SUMX(FILTER(...), ...) |
| 占比全是 100% | 分母没用 ALL 去掉筛选 | 分母写成 CALCULATE([总销售额], ALL(产品))，把产品筛选去掉 |
| 利润率在总计行不对 | 总计行是汇总后再算比率，不是把各行比率加总 | 这是正确的：总计利润率 = 总利润 / 总销售额 = 30.12%，不要手工加各行比率 |
| 度量值到处重复定义 | 同一个总销售额在多张表上各写一遍 | 统一建在事实表上，其他地方只引用 [总销售额] |
| 目标完成率超过 100% 还显示正常 | 目标值写死在公式里，目标变了没人改 | 目标值单独建一张参数表或度量值，公式里引用，不要写死数字 |
