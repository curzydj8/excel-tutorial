## 2. 基础概念

### 2.1 组合的思路

单个函数解决单个问题，组合解决真实问题。高价值订单利润要先筛（FILTER）再逐行算（SUMX）；排名要先定范围（ALL）再比大小（RANKX）；动态标题要先取当前筛选值（SELECTEDVALUE）再拼字符串。写高级 DAX 时先画三步：筛出哪些行、对每行算什么、最后怎么汇总。

### 2.2 RANKX 与 TOPN 的区别

- **RANKX**：给每一行一个名次。返回的是数字（1、2、3），适合放在透视表里当一列看。
- **TOPN**：返回前 N 行组成的一张子表。返回的是表，不能直接当度量值，要配 SUMX 或 COUNTROWS 用，适合算“前 N 名合计”。

两者都要注意并列：RANKX 默认并列同名次、下一名次跳号；TOPN 遇到并列边界时可能多返回一行（例如第 2 名和第 3 名同分，TOPN(2) 会返回 3 行），做“前 N 名合计”时要先检查边界有没有并列。

### 2.3 动态标题与动态度量值

- **动态标题**：一个度量值返回文本，标题引用它。切片器选华东，标题变成“华东地区销售额”；不选，标题是“全部地区销售额”。
- **动态度量值**：一个切片器切换指标。参数表里放三行（销售额、利润、利润率），度量值用 SWITCH 判断当前选了哪一行，再返回对应的基础度量值。透视表的值只拖这一个动态度量值，切换切片器就换指标。

## 3. 操作步骤

1. 确认 01 至 04 篇的模型与度量值都在：总销售额、总利润、利润率、去年同期销售额、同比增长率（待补图）。
2. 在产品表新建度量值“产品销售额排名”：公式见 5.2 节；再在客户表新建“地区销售额排名”。
3. 在订单表新建度量值“前 2 产品销售额”：用 TOPN + SUMX，公式见 5.3 节。
4. 在订单表新建度量值“动态标题”：公式见 5.4 节；透视表标题栏引用这个度量值。
5. 新建参数表“指标选择”（三行：销售额、利润、利润率），不与任何表建关系；再建动态度量值“动态指标”，公式见 5.5 节。
6. 按 6 节做销售分析仪表盘：KPI 卡片 6 个、产品排名表、地区排名表、月度同比表各一张透视表，拼在一张工作表上。
7. 按 7 节做库存周转分析：库存表进模型、与产品表建关系，建周转率与周转天数两个度量值，输出周转表并标出滞销品。

## 5. 公式和代码

DAX 语法经 Microsoft 官方文档核对；输入表与预期结果经 Python 独立验算；未在 Excel 内执行验证。以下示例的输入表均为配套示例文件里的表。

### 5.1 SUMX + FILTER 组合：高价值订单利润

先筛出金额大于 8000 的订单，再逐行算利润、汇总。

```dax
高价值订单利润 = SUMX(FILTER(订单, 订单[金额] > 8000), 订单[数量] * (RELATED(产品[单价]) - RELATED(产品[成本])))
```

运行结果：高价值订单利润 = 11100。输入是 4 笔高价值订单：O001 利润 2400、O002 利润 2700、O007 利润 3600、O012 利润 2400；2400+2700+3600+2400 = 11100，占总利润 22770 的 48.75%（11100 / 22770）。

为什么不能只用 SUM：利润没有现成的列，SUM 只能对已有列求和；利润 = 数量 ×（单价 − 成本）是逐行算出来的，必须用 SUMX。FILTER 先筛、SUMX 再算，顺序不能反。

### 5.2 RANKX 排名：产品与地区

```dax
产品销售额排名 = RANKX(ALL(产品[产品名称]), [总销售额], , DESC)
```

运行结果（透视表行是产品名称）：

| 产品名称 | 总销售额 | 排名 |
|---|---|---|
| 电脑 | 40000 | 1 |
| 手机 | 15000 | 2 |
| 耳机 | 9000 | 3 |
| 显示器 | 9000 | 3 |
| 键盘 | 2600 | 5 |

耳机与显示器都是 9000，并列第 3；下一名次直接跳到第 5，没有第 4 名。这是 RANKX 默认的并列规则（ties 参数默认跳号）。如果要并列后不跳号，把 ties 参数写成 DENSE：第 5 名会变成第 4 名。

```dax
地区销售额排名 = RANKX(ALL(客户[地区]), [总销售额], , DESC)
```

运行结果（透视表行是地区）：华东 29600 第 1 名、华南 28000 第 2 名、华西 11000 第 3 名、华北 7000 第 4 名。没有并列，名次连续。

注意：RANKX 的第一个参数必须用 ALL 去掉筛选，否则透视表每行只剩自己，排名永远是 1。

### 5.3 TOPN：前 N 名合计

```dax
前2产品销售额 = SUMX(TOPN(2, ALL(产品[产品名称]), [总销售额], DESC), [总销售额])
```

运行结果：前 2 产品销售额 = 55000（电脑 40000 + 手机 15000）。前 2 名占总销售额的 72.75%（55000 / 75600）。

```dax
前3地区销售额 = SUMX(TOPN(3, ALL(客户[地区]), [总销售额], DESC), [总销售额])
```

运行结果：前 3 地区销售额 = 68600（华东 29600 + 华南 28000 + 华西 11000）。前 3 名占总销售额的 90.74%（68600 / 75600）。

注意：TOPN 不响应切片器筛选（第一个参数用了 ALL），要做“所选年份的前 N 名”时，把 ALL 换成 ALLSELECTED。

### 5.4 动态标题

```dax
动态标题 = "销售额 - " & IF(HASONEVALUE(客户[地区]), VALUES(客户[地区]), "全部地区")
```

运行结果：切片器选华东时，动态标题 = "销售额 - 华东"；不选任何地区时，动态标题 = "销售额 - 全部地区"。HASONEVALUE 判断当前筛选是不是唯一值，VALUES 取出这个唯一值。

进阶版：标题里带上数字。

```dax
动态标题含数字 = "销售额 - " & IF(HASONEVALUE(客户[地区]), VALUES(客户[地区]), "全部地区") & "：" & FORMAT([总销售额], "#,##0")
```

运行结果：选华东时显示“销售额 - 华东：29,600”；不选时显示“销售额 - 全部地区：75,600”。

### 5.5 动态度量值：SWITCH + 参数表

先建一张不建关系的普通表“指标选择”，一列“指标”，三行：销售额、利润、利润率。再写一个度量值：

```dax
动态指标 = SWITCH(SELECTEDVALUE(指标选择[指标], "销售额"),
    "销售额", [总销售额],
    "利润", [总利润],
    "利润率", [利润率],
    [总销售额])
```

运行结果：切片器选“利润”时，动态指标 = 22770；选“利润率”时，动态指标 = 30.12%；选“销售额”或不选时，动态指标 = 75600。透视表的值只拖这一个度量值，切换切片器就换指标，不用做三张透视表。

## 6. 实际工作场景：案例 1 销售分析仪表盘

背景：销售总监每月要一页仪表盘：KPI 卡片、产品排名、地区排名、月度同比，四块内容一张表讲清。

输入表：订单表 12 行、产品表 5 行、客户表 4 行、日期表 455 行（配套示例文件）。

步骤：

1. KPI 卡片区：6 个度量值各占一个单元格（用透视表或直接用 CUBEVALUE 引用度量值）。
2. 产品排名表：透视表行拖产品名称，值拖总销售额与产品销售额排名。
3. 地区排名表：透视表行拖地区，值拖总销售额与地区销售额排名。
4. 月度同比表：透视表行拖日期表的月，值拖总销售额、去年同期销售额、同比增长率。

预期结果：

KPI 卡片：

| 指标 | 结果 |
|---|---|
| 总销售额 | 75600 |
| 总利润 | 22770 |
| 利润率 | 30.12% |
| 订单笔数 | 12 |
| 客单价 | 6300 |
| 2026 年一季度同比 | 71.54% |

产品排名：电脑 40000 第 1 名、手机 15000 第 2 名、耳机 9000 并列第 3 名、显示器 9000 并列第 3 名、键盘 2600 第 5 名。

地区排名：华东 29600 第 1 名、华南 28000 第 2 名、华西 11000 第 3 名、华北 7000 第 4 名。

月度同比：2026-01 同比 10.53%、2026-02 同比 153.33%、2026-03 同比 300.00%。

结论：电脑一个产品占 52.91%，华东一个地区占 39.15%，前 2 产品合计 55000 占 72.75%；增长主要靠 3 月（同比 300.00%），2 月是淡季（环比 -63.81%）。

## 7. 实际工作场景：案例 2 库存周转分析

背景：仓库主管要知道哪种产品压货最严重。库存表 5 行（配套示例文件库存表工作表）：

| 产品编号 | 产品名称 | 期初库存（件） | 期末库存（件） |
|---|---|---|---|
| P001 | 电脑 | 20 | 12 |
| P002 | 手机 | 15 | 10 |
| P003 | 耳机 | 50 | 20 |
| P004 | 键盘 | 30 | 17 |
| P005 | 显示器 | 10 | 4 |

步骤：

1. 库存表进数据模型，与产品表按产品编号建一对多关系（产品表 1 对库存表多）。
2. 建度量值“销售数量”：`= SUM(订单[数量])`；建度量值“平均库存”：`= DIVIDE(SUM(库存[期初库存]) + SUM(库存[期末库存]), 2)`。透视表行是产品名称时，每行只有库存表的一行，公式退化为（期初 + 期末）/ 2，例如电脑 (20+12)/2 = 16。
3. 建度量值“库存周转率”：`= DIVIDE([销售数量], [平均库存])`。
4. 建度量值“库存周转天数”：`= DIVIDE(365, [库存周转率])`，年化口径。

预期结果（销售数量取自订单表：电脑 8 件、手机 5 件、耳机 30 件、键盘 13 件、显示器 6 件）：

| 产品名称 | 销售数量 | 平均库存（件） | 周转率（次） | 周转天数（天） |
|---|---|---|---|---|
| 电脑 | 8 | 16.0 | 0.50 | 730.0 |
| 手机 | 5 | 12.5 | 0.40 | 912.5 |
| 耳机 | 30 | 35.0 | 0.86 | 425.8 |
| 键盘 | 13 | 23.5 | 0.55 | 659.8 |
| 显示器 | 6 | 7.0 | 0.86 | 425.8 |

金额口径复核：销售成本合计 52830（电脑 30400 + 手机 10500 + 耳机 4500 + 键盘 1430 + 显示器 6000）；平均库存金额合计 101885（电脑 60800 + 手机 26250 + 耳机 5250 + 键盘 2585 + 显示器 7000）；整体周转率 0.52 次（52830 / 101885），周转天数 703.9 天（365 / 0.52）。

结论：手机周转最慢（0.40 次、912.5 天），建议优先促销；耳机与显示器周转最快（0.86 次、425.8 天），可以补货。周转天数超过 700 天的只有电脑（730.0 天）与手机（912.5 天），两者合计平均库存金额 87050，占总平均库存金额的 85.45%（87050 / 101885），压货主要集中在这两个产品上。

## 8. 常见错误

| 错误现象 | 原因 | 解决方案 |
|---|---|---|
| RANKX 每行排名都是 1 | 第一个参数没用 ALL 去掉筛选 | RANKX(ALL(产品[产品名称]), [总销售额], , DESC)，先去掉筛选再排名 |
| 并列后名次跳号觉得是错 | RANKX 默认跳号规则 | 这是默认行为；要连续名次用 DENSE 参数 |
| TOPN 返回的行比 N 多 | 边界值并列，TOPN 把并列行都返回 | 检查边界值；做合计时接受多行，或改用 RANKX 小于等于 N 的 FILTER |
| TOPN 不随切片器变化 | 第一个参数用了 ALL | 要响应切片器时把 ALL 换成 ALLSELECTED |
| 动态标题一直显示“全部地区” | 切片器选的是多值，或字段拖错 | HASONEVALUE 要求唯一值；多选时显示默认值，可改用 CONCATENATEX 拼接多个值 |
| 动态度量值切换后数字不变 | 参数表与模型建了关系，或 SELECTEDVALUE 取不到值 | 参数表不要建关系；检查切片器字段是不是参数表的指标列 |
| SUMX + FILTER 算得很慢 | FILTER 在百万行上逐行筛 | 能用 CALCULATE 简单条件先筛就用 CALCULATE；FILTER 只留给复杂条件 |
| 仪表盘刷新后数字全变空白 | 关系被误删，或日期表标记丢了 | 检查关系视图三条线是否还在；重新标记日期表 |
