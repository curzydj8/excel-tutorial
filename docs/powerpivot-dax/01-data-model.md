## 2. 基础概念

### 2.1 什么是数据模型

数据模型是 Power Pivot 里的一组表加上表之间的关系。普通 Excel 工作表之间是孤立的，跨表取值要写 VLOOKUP；放进数据模型后，表与表通过关系连起来，透视表和 DAX 公式可以直接跨表计算，不用再写一堆查找公式。

本篇配套示例共 4 张表：订单表 12 行、产品表 5 行、客户表 4 行、日期表 455 行（2025-01-01 至 2026-03-31，每日一行）。行数与配套示例文件逐项一致。

### 2.2 事实表与维度表

- **事实表**：记录业务事件的表，行数多、数字列多。本例中订单表是事实表：每一行是一笔订单，含订单号、日期、客户编号、产品编号、数量。
- **维度表**：描述事实的表，行数少、文本列多。本例中产品表、客户表、日期表都是维度表：产品表描述卖的是什么，客户表描述卖给谁，日期表描述发生在何时。

判断方法：问一句“这张表的一行代表一次业务发生，还是代表一个固定对象？”前者是事实表，后者是维度表。

### 2.3 主键与外键

- **主键**：维度表里唯一标识一行的列，值不能重复、不能为空。产品表的产品编号（P001 至 P005）、客户表的客户编号（C001 至 C004）、日期表的日期（455 个日期各不相同）都是主键。
- **外键**：事实表里指向维度表主键的列，值可以重复。订单表的产品编号、客户编号、日期都是外键：O001 和 O007 的产品编号都是 P001，说明两笔订单卖的是同一种产品。

主键与外键的值必须能对上号：订单表里出现的每一个产品编号，产品表里必须有一行；否则关系建不起来，透视表里会出现空白行。

### 2.4 一对多关系与关系方向

本例的三段关系都是一对多：

| 关系 | 一端（维度表） | 多端（事实表） | 连接键 |
|---|---|---|---|
| 产品与订单 | 产品表（1） | 订单表（多） | 产品编号 |
| 客户与订单 | 客户表（1） | 订单表（多） | 客户编号 |
| 日期与订单 | 日期表（1） | 订单表（多） | 日期 |

- **关系方向**：默认是单向筛选，从一端筛向多端。点选产品表里的“电脑”，订单表自动只剩电脑的 4 笔订单；反过来，在订单表里筛一个订单号，产品表不会跟着动。
- **交叉筛选方向**：双向筛选会让筛选在两张表之间互相传导。初学者先用单向，够用且不容易出歧义；只有“两个维度表要互相筛选对方”时才考虑双向，例如既按产品筛客户、又按客户筛产品。

### 2.5 星型模型

以事实表为中心、维度表围在四周，就是星型模型：订单表在中间，产品表、客户表、日期表像星星的角一样连在它上面。星型模型是 Power Pivot 的标准形态，优点是关系简单、计算快、DAX 公式好写。本例的 4 张表正好构成一个星型：1 张事实表加 3 张维度表。

不要把维度表再连维度表（例如产品表连客户表），那会变成雪花型，关系一多就容易出现筛选歧义，初学者先不碰。

## 3. 操作步骤

1. 启用 Power Pivot 加载项：文件 → 选项 → 加载项 → 管理选 COM 加载项 → 转到 → 勾选 Microsoft Power Pivot for Excel → 确定。功能区出现“Power Pivot”选项卡即成功（待补图）。
2. 把产品表转成超级表：选中产品表任意单元格 → 插入 → 表格 → 确认“表包含标题” → 确定。订单表、客户表、日期表同样处理（待补图）。
3. 打开 Power Pivot 窗口：Power Pivot → 管理。窗口里先是空的，还没有表。
4. 添加表到数据模型：在 Power Pivot 窗口点“添加到数据模型”→ 在工作表里选中订单表区域 → 确定；产品表、客户表、日期表重复同样操作。4 张表出现在模型里后，点“关系视图”（待补图）。
5. 建立产品与订单的关系：在关系视图中，把产品表的“产品编号”拖到订单表的“产品编号”上，松开鼠标，弹出“创建关系”对话框，确认“产品表（1）→ 订单表（多）”后点“创建”（待补图）。
6. 建立客户与订单、日期与订单的关系：同样拖线两次，分别连客户编号、日期。三条关系线出现后，关系视图里订单表居中、三张维度表围在四周，就是星型（待补图）。
7. 验证关系：回 Excel 插入一张数据透视表，勾选“将此数据添加到数据模型”；把产品表的“产品名称”拖到行、订单表的“数量”拖到值。若电脑一行显示 8（2+1+3+2），关系就是通的。
8. 保存文件：按 Ctrl+S 保存为 xlsx。数据模型随文件一起保存，下次打开不用重建。

## 5. 公式和代码

本篇只用一个度量值做验证。度量值写在 Power Pivot 窗口的度量值区域，或在透视表字段列表里右键事实表新建。DAX 语法经 Microsoft 官方文档核对；输入表与预期结果经 Python 独立验算；未在 Excel 内执行验证。

```dax
总销售额 = SUM(订单[金额])
```

运行结果：总销售额 = 75600（订单表金额列 = 数量 × 单价，12 行合计：10000+9000+3000+1000+3000+5000+15000+6000+6000+1600+6000+10000 = 75600）。

```dax
订单笔数 = COUNTROWS(订单)
```

运行结果：订单笔数 = 12（订单表共 12 行）。

```dax
客单价 = DIVIDE([总销售额], [订单笔数])
```

运行结果：客单价 = 6300（75600 / 12）。

按产品分组的预期结果（透视表行是产品名称，值是总销售额）：

| 产品名称 | 总销售额 |
|---|---|
| 电脑 | 40000 |
| 手机 | 15000 |
| 耳机 | 9000 |
| 显示器 | 9000 |
| 键盘 | 2600 |
| 总计 | 75600 |

按地区分组的预期结果（透视表行是客户表的地区，值是总销售额）：

| 地区 | 总销售额 |
|---|---|
| 华东 | 29600 |
| 华南 | 28000 |
| 华西 | 11000 |
| 华北 | 7000 |
| 总计 | 75600 |

两张分组表的总计都是 75600，互相印证：如果某张分组表总计对不上，说明关系丢了行或键值对不上，先查外键有没有写错。

## 6. 实际工作场景

场景：月度销售汇总不用 VLOOKUP。

- 背景：销售部每月给一张订单明细（订单号、日期、客户编号、产品编号、数量），产品信息在另一张产品表（产品编号、产品名称、类别、单价、成本），客户信息在第三张客户表（客户编号、客户名称、地区）。
- 旧做法：在订单表旁加 VLOOKUP 列取单价、再加一列取地区，公式拖 12 行；下月新来 500 行订单，公式要重拖，VLOOKUP 一旦把查找范围写少一行就会返回错误值。
- 新做法：4 张表进数据模型、连好 3 段关系；透视表行拖产品名称、值拖一个总销售额度量值，立刻得到电脑 40000、手机 15000 的分产品汇总；行换成地区，立刻得到华东 29600、华南 28000 的分地区汇总。下月追加订单行后点“刷新”，数字自动更新，公式一个不用改。
- 结果：同一份模型既能按产品看、又能按地区看、还能按月看，不用为每个角度各建一张 VLOOKUP 辅助表。

## 7. 百万行性能专节

### 7.1 压缩原理

Power Pivot 把数据存成列式存储（VertiPaq 引擎）：同一列的值存在一起，重复值只存一次字典编码。例如订单表的产品编号列只有 P001 至 P005 五种值，12 行也好、100 万行也好，字典里只存 5 个条目，每行只存一个很短的编码。这就是“百万行不卡”的来源：行数涨上去，文件体积和内存占用涨得很慢。

压缩效果取决于列的重复程度：类别、地区、日期这类低基数列压得很好；订单号、身份证号这类每行都不同的高基数列几乎压不动。

### 7.2 百万行建模 5 条要点

1. 只导需要的列：源表里用不上的列（备注、操作人、导入时间）不要进模型，每多一列就多一份字典和内存。
2. 主键外键用整型：产品编号 P001 这类文本键能用，但百万行时整型键（1、2、3）关系运算更快；文本键只在行数不大时用。
3. 日期列只保留日期、不要带时间：带时间的日期时间列基数极高，压缩差、时间智能函数也不认；日期表用纯日期列。
4. 计算列能省则省：计算列是逐行算好存起来的，占内存；能用度量值（查询时现算）解决的，不要写计算列。
5. 导入模式优先：数据先导进模型再算，比 DirectQuery（每次查询都回数据库）快得多；百万行以内优先用导入模式。

## 8. 常见错误

| 错误现象 | 原因 | 解决方案 |
|---|---|---|
| 功能区没有 Power Pivot 选项卡 | 加载项未启用，或当前版本无此功能 | 文件 → 选项 → 加载项 → COM 加载项 → 勾选后重启 Excel；家庭版无 Power Pivot 需换版本 |
| 拖线后提示“关系需要唯一值” | 维度表主键列有重复值或空值 | 检查主键列去重、补空值；产品编号 P001 不能出现两次 |
| 透视表出现“(空白)”行 | 订单表外键值在维度表里找不到 | 检查外键拼写，例如产品编号多了空格；用删除重复项加条件格式定位孤儿值 |
| 分组总计与明细合计对不上 | 关系方向错，或存在重复关系 | 只保留一段关系；确认箭头从一端指向多端；删除多余的关系线 |
| 刷新后数字不变 | 追加的新行在超级表范围之外 | 把源数据先转成超级表再进模型；或在 Power Pivot 里点“刷新”而非只刷新透视表 |
| 模型文件体积突然变大 | 导进了高基数列（如订单备注、时间戳） | 删除无用列；日期时间列拆成纯日期列；文本键改整型键 |
| 筛选产品后客户表没有反应 | 关系是单向筛选，筛不动反方向 | 这是正常行为；确实需要双向时再把交叉筛选方向改为“双向”，改前确认没有歧义环路 |
